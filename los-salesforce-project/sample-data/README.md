## Loan history and per-record documents

The three Harborview loans model a multi-year lending relationship with the same borrower. Each loan links to its own Opportunity, and the document is uploaded into that **Opportunity's** Box folder by `seed-los-loan-files.apex` (via `BoxEmailAttachmentUploader`); Opportunity is the Box-mapped object:

| Record | Status | File (in the loan's Opportunity Box folder) | Static resource |
|---|---|---|---|
| `LN-2023-0311` | Closed | `harborview-loan-agreement-2023-executed.pdf` | `Los_Sample_Loan_2023_Executed` |
| `LN-2025-0148` | Closed | `harborview-loan-agreement-2025-executed.pdf` | `Los_Sample_Loan_2025_Executed` |
| `LN-2026-0042` | Underwriting | `harborview-term-sheet-2026-markup.docx` (Word, the borrower's markup) | `Los_Sample_Term_Sheet_2026_Markup` |

A fourth resource, `Los_Sample_Loan_Application` (`harborview-loan-application-2026.pdf`), is the attachment `demo-email-intake.apex` sends through the email intake handler.

Prior years get the **executed loan agreement PDF**, whose Schedule 1 records the negotiated 70% LTV and 1.30x DSCR covenants; the current year gets the borrower's marked-up term sheet in **Word**, which weakens the DSCR test in Section 9.3 and adds FF&E to Schedule A. Assets are generated by `scripts/generate_sample_loan_assets.py` (PDFs) and `scripts/generate_docgen_templates.py` (the markup docx). The upload targets the loan's **Opportunity** Box folder (`LOS_Loan__c` is not Box-mapped, so each loan carries its own Opportunity).

## Relationships populated

- `LOS_Loan__c.Borrower_Account__c` references `Account` (all three Harborview loans point at the same Harborview Logistics account, which is what the `LOS_Borrower_Access` sharing set filters on).
- `LOS_Loan__c.Opportunity__c` references `Opportunity`; every Harborview loan links to its own Opportunity (2023, 2025, 2026), which is what carries the Box folder the document lands in.
- Opportunities are related to their owning Accounts.
- Contacts are related to their owning Accounts.

## Seed behavior

- **Idempotent and rerunnable**
  - Accounts by `Name`
  - Contacts by `Email`
  - Opportunities by `Name` + `AccountId`
  - Loans by `Loan_ID__c`
- Existing records are updated with required relationship fields and the numeric term fields so links and figures stay aligned.
- Missing records are created.

## Files

- `los-sample-records.bcl`: descriptive sample-record spec in the repository's BCL format. Mirrors the Apex values for packaging; it is not read at seed time.
- `../scripts/seed-los-salesforce-sample-data.apex`: Apex executable and source of truth for the records.
- `../scripts/seed-los-sample-data.sh`: `sf` wrapper for the records seed.
- `../scripts/seed-los-loan-files.apex`: uploads each loan's document into its Box record folder.
- `../scripts/seed-los-loan-files.sh`: `sf` wrapper for the file upload.

## Run

Seed records, deploy the loan-file static resources, then upload the files into each record's Box folder:

```bash
# 1. records
./scripts/seed-los-sample-data.sh agentforce
# 2. deploy the static resources (once)
sf project deploy start --target-org agentforce --source-dir force-app/main/default/staticresources
# 3. upload each loan's document into its Box record folder
./scripts/seed-los-loan-files.sh agentforce
```

None of this has been run against a live org yet for the loans variant; the CLM predecessor proved the same scripts live.

Optional: to also populate the shared **06 - Executed Loan Documents** Box folder (the App's Executed Loans view), add the executed PDFs to `scripts/demo_operator.py` `UPLOADS`.
