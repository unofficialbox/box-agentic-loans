### 3. 🔧 TODO: Prefer Metadata Search + Box MCP Direct

**Problem:** Agent uses inefficient search patterns:
- LOS wrapper when Box MCP is faster
- Keyword/filename search when metadata is available
- File listing + filtering when metadata query would be precise

**Solution:** **METADATA FIRST**, then Box MCP direct, then LOS wrapper.

**Search Priority:**
1. ✅ **Metadata query** - For searches by type/risk/status/borrower
   - Box connector → `query_metadata(template="losDocument", query="policyRisk='Critical'")`
   - Precise, fast, indexed
2. ✅ **Box MCP direct** - For Box-native operations (AI, preview, Hub)
3. ✅ **LOS connector** - Only when Salesforce data or governance needed

**Use Box MCP `query_metadata` for:**
- Find documents by risk level: `policyRisk='Critical'`
- Find documents by type: `documentType='Term Sheet'`
- Find documents by loan: `loanReference='LN-2026-0042'`
- Find documents by borrower: `borrowerEntity='Dockwright Logistics'`
- Find pending reviews: `reviewStatus='Pending'`

**Use LOS Salesforce connector for:**
- Loan record operations (CRUD on `LOS_Loan__c`)
- Cross-system operations (extract + validate against Salesforce + credit policy)
- Governed actions (`extractLoanTerms`, `applyLoanTerms`)
- Getting governed document set for a specific loan (`getLoanPackage`)

**Fix Location:** Update Copilot + CLAUDE.md instructions

**Status:** ✅ CLAUDE.md updated with metadata-first strategy

### 5. ✅ FIXED: Doc Gen Scope + Empty Placeholders Documentation

**Problems:**
1. **403 Error:** ✅ FIXED - LOS CCG app now has Box Doc Gen scopes
2. **Empty Placeholders:** Generated files show `{{terms.requestedPosition}}` instead of actual values

**Root Causes:**
1. **403:** ✅ FIXED - Scope added to LOS CCG app
2. **Empty Placeholders:** Agent didn't provide analysis fields when calling action

**The Action Requires:**
```apex
req.loanReference = "LN-2026-0042";  // Required
req.policyAtIssue = "...";           // Required
req.requestedPosition = "...";       // Optional, but fills placeholder
req.approvedPosition = "...";        // Optional, but fills placeholder
req.exceptionPosition = "...";       // Optional, but fills placeholder
req.owner = "...";                   // Optional, defaults to "Credit Risk"
req.precedentSummary = "...";        // Optional, but fills placeholder
req.proposedTerms = "...";           // Optional, but fills placeholder
req.termSheetReference = "...";      // Optional, but fills placeholder
```

If optional fields are blank, they become '--' in the letter.

**The Agent Must:**
1. Extract terms from marked-up term sheet
2. Validate against credit policy Hub
3. Cite specific policy IDs (LOS-LTV-001, etc.)
4. Research prior loans with borrower
5. Draft proposed terms
6. Pass ALL analysis to generateCommitmentLetter

**Solution: Use Box MCP**

Box MCP connector for Beat 5 (MCP-first strategy):

```javascript
Box MCP → create_document_from_template({
  template_id: "2454763922014",
  destination_folder_id: <from getLoanPackage>,
  fields: {
    loan: { id, borrower, loanAmount, status, termSheetReference },
    terms: { policyAtIssue, requestedPosition, approvedPosition, 
             exceptionPosition, owner, risk, proposedTerms },
    precedent: { summary },
    letter: { preparedOn, preparedBy }
  }
})
```

All `fields` must come from analysis (extractLoanTerms, policy Hub, listLoans), not placeholder text.

**Status:** 
- ✅ Box MCP approach documented in CLAUDE.md
- ✅ Empty placeholders: Documented agent workflow in `docs/DOCGEN-GUIDE.md`
